# quiz-app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the invite-only, timed, multi-answer MCQ quiz app described in the spec. It is served at `akshayprabhakant.com/quiz`, with its API at `/quiz/api/*`.

**Architecture:**
- **Backend:** a Python Cloudflare Worker over D1. The domain logic (timing, scoring, grading, shuffling) is pure Python. Persistence sits behind ABC ports. The HTTP logic lives in a runtime-free `Api` class, which both the Worker entrypoint and a stdlib `local_server.py` adapt.
- **Frontend:** a Next.js static export (`basePath: '/quiz'`) served by a tiny static-assets Worker. The UI is the approved `design/sparks.html`, rebuilt as React components.

**Tech Stack:** Python ≥3.11 stdlib only (runtime), `workers-py`/`pywrangler` + `pytest` (dev). D1 (SQLite). Next.js 15 + React 19 + TypeScript, `react-markdown` + `remark-gfm`. Wrangler. GitHub Actions.

**Spec:** `docs/design.md`. Approved schema: `backend/migrations/0001_init.sql`. Approved UI: `design/sparks.html`. Reference implementation for every convention not stated here: `~/github/ai-chat-archive` (backend `chat_archive/`, frontend `app/`, `lib/`, `.github/workflows/ci.yml`).

## Global Constraints

- All API paths are prefixed `/quiz/api`. Every API route requires an identity. No identity means `401 {"error": "sign-in required"}`.
- Error bodies are always `{"error": "<message>"}`. Status mapping: `NotFound`→404, `Conflict`→409, `Invalid`→422, `Forbidden`→403.
- Another user's attempt, or an unpublished set requested by a solver, is **404, never 403**.
- JSON keys are `snake_case` on the wire. Times are integer epoch **milliseconds**.
- No solver-facing payload may contain `is_correct`, `correct`, `explanation`, `score` or `awarded_points` while the attempt is `in_progress`.
- The server clock decides time. Constants (backend): `GRACE_MS = 10_000`. Constants (frontend): `AMBER_BELOW_S = 300`, `RED_BELOW_S = 60`, `AUTOSAVE_DEBOUNCE_MS = 400`, `TIMES_UP_OVERLAY_MS = 1500`.
- Admins are the comma-separated, case-insensitive emails in the Worker **secret** `ADMIN_EMAILS`, set with `wrangler secret put`. It is never written in `wrangler.jsonc`, so your email stays out of the repo. Everyone else is a `solver`.
- `display_name` is trimmed, 1–60 characters.
- Set names are derived: `[subtopic] · [Easy|Medium|Hard] · [Scenario] · Set {seq}`, joined with `" · "`. A non-null `title` replaces the whole derived name.
- Backend runtime code is **stdlib only** (Python Workers packages are a deploy risk). Tests are stdlib `unittest`, runnable both as `python3 test/test_x.py` and via `uv run pytest`, like the archive.
- Theme tokens, type and components must match `design/sparks.html` exactly. It is the approved FE. Light only.
- **Sketch-only, must not ship** (verify in Task 10): the "Spark, not the product…" note, the sample `TOPICS` data, `demoSeconds` / the 60-second timer and its scaled 30 s / 10 s thresholds, the `#play`/`#results` hash hooks, and `you@example.com`.
- Commit after each task. Never push or deploy. The user does both.

## Review Focus

1. **Two tabs on the same quiz.** Two simultaneous "Start" clicks must yield one attempt, and saving from both tabs is last-write-wins per question. Pinned in Task 5: `test_concurrent_start_returns_same_attempt`.
2. **Backgrounded tab or a laptop that slept.** Browsers throttle timers, so the countdown must be recomputed from `deadline_at` on every tick, never decremented. On wake it must show the true remaining time (or fire timeout immediately). Pinned in Task 8: `remainingSeconds` tests.
3. **Autosave in flight at the buzzer, or a save that fails.** Submit and timeout must flush pending saves first. A failed save stays pending and shows "Not saved — retrying" rather than silently dropping an answer. Pinned in Task 9: `SaveQueue` tests.
4. **Guessing someone else's attempt id.** Resume, save, submit and results on another user's attempt are all 404. Pinned in Task 6: `test_foreign_attempt_is_404_everywhere`.
5. **Author-written markdown containing raw HTML** (`<img onerror>`, `<script>`) must render as text. The frontend uses `react-markdown` **without** `rehype-raw`. Pinned in Task 8: `Markdown` renders `<script>` literally (build-time check plus manual step).

## Wire contract

The backend serializers and `frontend/lib/types.ts` both implement exactly this. Field order is not significant.

  status: 'in_progress' | 'submitted' | 'expired'; started_at: number; finished_at: number | null;

**Interfaces:**

  - `AllOrNothing`, `PartialCredit`
  - `ScoringPolicyFactory.for_name(name: str) -> ScoringPolicy`. It is backed by a module-level registry `{"all_or_nothing": AllOrNothing, "partial": PartialCredit}` and raises `Invalid` on an unknown name. `ScoringPolicyFactory.names() -> frozenset[str]`.
  - `grade(keys: list[QuestionKey], selections: dict[int, frozenset[int]], policy: ScoringPolicy) -> GradeResult`. `is_correct` is always an exact match (`selected == correct`). A blank answer scores 0. `max_score = sum(points)`.
  - `display_order(attempt_id: str, questions: list[QuestionForSolver], shuffle_questions: bool, shuffle_options: bool) -> list[QuestionForSolver]`. Use `random.Random(attempt_id)` for question order, and `random.Random(f"{attempt_id}:{question.id}")` for each question's options. It is deterministic across processes (str seeds hash by SHA-512).

- [ ] **Step 1: Write `ci.yml`.** Adapt the archive's workflow. The test job runs each `backend/test/test_*.py`, then `uv sync && uv run pytest -q`, then `npm ci && npm run test:lib && npm run build:check` in `frontend/`. Deploy jobs run only on `main` after tests pass:

- [ ] **Step 2: Write `docs/deploy.md`.** It is a checklist for the user, in this order. **Access is set up before anything is deployed**, so `/quiz` is never publicly reachable, not even for a minute.

  **A. Cloudflare One → Access → Applications** (`dash.cloudflare.com/<account>/one/access-controls/apps`). Add a **new** application. Don't add destinations to the archive's existing app: one app has one policy, so anyone invited to the quiz would also get through to the archive's copy desk.
  1. **Add an application → Self-hosted.** Name it `Quiz Room`.
  2. **Destinations** (public hostname). Add two, both with domain `akshayprabhakant.com`:
     - path `quiz`
     - path `quiz/*`

     Both are needed, because a wildcard "does not cover the parent path" (`ai-chat-archive/docs/access-limits.md` §2). `quiz/*` already covers `/quiz/api/*`, so the API needs no destination of its own.
  3. **Session duration:** your choice. 24 h means friends rarely re-enter a code mid-week; 1 week is fine for an invite-only quiz.
  4. **Login methods:** One-time PIN. It is already enabled account-wide for the archive; if it isn't listed, enable it under Settings → Authentication.
  5. **Policy:** name `Invited solvers`, Action **Allow**, Include → **Emails** → you plus each invitee.
     - **Never** use Include → "Login Methods: One-time PIN" alone. That lets *any* email in (`access-limits.md` §6).
     - Optional: create an Access **group** "Quiz solvers" first and Include that group, so inviting someone later means editing one list.
  6. Leave the CORS settings, the App Launcher and the cookie settings at their defaults. Everything is same-origin.
  7. Save. Then check: `curl -sI https://akshayprabhakant.com/quiz` should give `302` to `<team>.cloudflareaccess.com` (GitHub Pages is still the origin at this point, and that's fine).

  **B. D1** (CLI, not the dashboard).
  - Run `cd backend && npx wrangler d1 create quiz-app --location apac`, then paste the `database_id` into `backend/wrangler.jsonc`.
  - Run `npx wrangler d1 migrations apply quiz-app --remote`.

  **C. Admin secret.** Run `cd backend && npx wrangler secret put ADMIN_EMAILS` and enter your email. Wrangler creates the Worker if it doesn't exist yet.

  **D. Deploy.**
  - Run `cd backend && uv run pywrangler deploy`.
  - Run `cd frontend && npm run build && npx wrangler deploy`.
  - The routes come from the `wrangler.jsonc` files, so nothing is set in the dashboard. DNS for `akshayprabhakant.com` is already proxied (orange cloud), which routes require, because the archive relies on it too.

  **E. CI (optional, for deploy on push).** In the GitHub repo settings → Secrets, add `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. The archive's token can be reused if it has Workers Scripts Edit, Workers Routes Edit (zone `akshayprabhakant.com`) and **D1 Edit**. Otherwise create one from the "Edit Cloudflare Workers" template and add D1 Edit.

  - An email *not* on the policy gets "A code has been emailed to you", but no code ever arrives. That is Access's documented behaviour.

  **G. Inviting someone later:** add their email to the policy (or the group) from A.5. No deploy is needed.
